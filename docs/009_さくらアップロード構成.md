# 009_さくらアップロード構成

## 目的

CardCMSをさくらのレンタルサーバーへテストアップロードするための構成を整理する。

## テスト設置先

さくらサーバー側では、次の場所へ置く想定とする。

```text
www/
└── cardcms-test/
```

## テストURL

```text
https://ichiba-kogei.sakura.ne.jp/cardcms-test/
```

上記URLを開くと、`public/index.php` へ移動する。

直接開く場合は、次のURLでも確認できる。

```text
https://ichiba-kogei.sakura.ne.jp/cardcms-test/public/index.php
https://ichiba-kogei.sakura.ne.jp/cardcms-test/admin/login.php
```

## アップロードする構成

```text
cardcms-test/
├── .htaccess
├── index.php
├── admin/
├── api/
├── config/
│   ├── .htaccess
│   └── auth.php
├── database/
│   ├── .htaccess
│   └── cards.json
├── includes/
│   ├── .htaccess
│   └── auth.php
├── public/
│   ├── index.php
│   └── includes/
└── uploads/
```

現在のアップロード対象は42ファイル。

## アップロードしないもの

```text
.git/
.gitignore
.DS_Store
docs/
backup/
images/
assets/
CardCMS起動.command
README.md
config/auth.example.php
```

## 注意点

- `config/auth.php` はGitHubへ送らないが、サーバーには必要。
- `.gitignore` はローカルGit用なので、サーバーには不要。
- `database/cards.json` はサーバー上でCardCMSが読み書きするデータ本体。
- `uploads/` は画像フォルダなので必ずアップロードする。
- `database/`、`config/`、`includes/` は `.htaccess` で直接アクセスを拒否する。
- `admin/` と `api/` はログイン後だけ使える。
- `docs/` は開発用メモなので、テスト公開フォルダには置かない。

## さくらサーバーで確認すること

1. `https://ichiba-kogei.sakura.ne.jp/cardcms-test/` が公開ページへ移動する
2. 公開ページの画像が表示される
3. `admin/login.php` でログインできる
4. カード一覧が表示される
5. システム情報でPHPバージョンとPHP判定を確認する
6. テストでカードを追加・編集した場合、`database/cards.json` が更新される
7. `database/cards.json` をブラウザで直接開けない
8. `config/auth.php` をブラウザで直接開けない
