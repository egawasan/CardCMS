# CardCMS データベース設計書

Version 0.1

---

## 1. データベース概要

CardCMSではSQLiteを採用する。

理由

- サーバー設定が容易
- バックアップが簡単
- 小～中規模システムに適している
- 将来の業務システムにも対応できる

---

## 2. cardsテーブル

|項目名|型|必須|内容|
|------|---|---|------|
|id|INTEGER|○|カードID（主キー）|
|card_number|TEXT|○|内部管理用カード番号（例: 000001）|
|card_type|TEXT|○|カード種別（例: トップページ、お知らせ、サービス、会社情報、お問い合わせ）|
|layout|TEXT|○|表示レイアウト（例: Hero、Text、ImageLeft、ImageRight、Gallery、Contact）|
|slug|TEXT|○|管理用の識別名（例: main-visual）|
|title|TEXT|○|タイトル|
|body|TEXT|○|本文|
|image|TEXT||代表画像のファイル名またはURL|
|images|JSON||追加画像のファイル名またはURL一覧|
|category|TEXT||カテゴリー|
|sort_order|INTEGER||表示順|
|published|INTEGER|○|公開状態（0:非公開、1:公開）|
|created_at|TEXT|○|作成日時|
|updated_at|TEXT|○|更新日時|

---

## 3. カードJSON形式

CardCMSでは、1枚のカードを1つの情報ブロックとして扱う。

カード番号は内部管理用とし、実際の用途は `card_type` と `layout` で判断する。

```json
{
  "id": 1783491523,
  "card_number": "000001",
  "card_type": "トップページ",
  "layout": "Hero",
  "slug": "main-visual",
  "title": "メイン画像",
  "body": "",
  "image": "main.jpg",
  "images": [],
  "sort_order": 10,
  "published": true,
  "created_at": "2026-07-13 21:10",
  "updated_at": "2026-07-13 22:30"
}
```

---

## 4. カード種別

|種別|用途|
|---|---|
|トップページ|トップページを構成するカード|
|お知らせ|新着情報や告知用カード|
|サービス|サービス紹介用カード|
|会社情報|会社概要、所在地、沿革など|
|お問い合わせ|お問い合わせ導線やフォーム|
|採用|将来の採用ページ用|

---

## 5. レイアウト

|レイアウト|用途|
|---|---|
|Hero|メイン画像|
|Text|文章のみ|
|ImageLeft|左画像・右文章|
|ImageRight|右画像・左文章|
|Gallery|施工事例などの画像一覧|
|Contact|お問い合わせ|
